# CareBridge Roadmap

Updated 2026-10-12 to align with [confirmed planning report Version 1.1](PANELS_AND_PERMISSIONS_PLAN.md). Phases describe planned work. The earlier 16-week outline is superseded; dates require agreement on school needs and team capacity.

| Phase | Deliverable | Exit evidence |
| --- | --- | --- |
| 0: Validate | School workflows, policy, scoped permissions and prototype | School owners resolve open decisions using synthetic-data tasks |
| 1: Access | Four roles, restricted Sub-admin grants, assignments, verified guardian links, session revocation; design tokens and en/my structure | Cross-child/class access and self-elevation denied; language switching preserves input |
| 2: School records | Structure, attendance, assessments, actionable feedback and corrections | Missing values distinguished from zero/absence; concurrent edits handled and history preserved |
| 3: Reporting | Submission, review, publication, version snapshots and authorized PDF | Guardians cannot retrieve unpublished or other-child reports |
| 4: Growth/support | Activities, student voice, explicit audiences, agreed goals and family requests | Author-private drafts, sharing/withdrawal and revisions verified |
| 5: Family and configuration | Responsive family web, Flutter, branding preview/publish and bilingual report rendering | Consistent permissions across clients; English/Myanmar layout, fonts and PDF tested |
| 6: Pilot | Accessibility, backup/restore, training and controlled rollout | Workload and comprehension measured; governance/security checks pass before real-data use |

Next implementation priority after validation: synthetic Class 7A/7B demonstration proving that a restricted Sub-admin cannot access another class. A frontend build alone does not establish product readiness.
